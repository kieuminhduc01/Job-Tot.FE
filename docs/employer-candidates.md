# Employer candidate management

Routes: `/employer/talents`, `/employer/candidates`, `/employer/interviews`. All reuse EmployerHeader, AuthFooter and PageBreadcrumb. “Quản lý CV” in the employer header links to candidate management; the three pages share navigation tabs.

The API `/api/employer/candidates` requires the employer bearer policy and scopes every read/write to the authenticated recruiter's active company. It exposes metadata, paginated applicants, talent pool, submitted CV, stage moves, interview calendar/scheduling/cancellation and interviewer feedback. No global candidate directory or private CV belonging to another employer is exposed. Talent pool entries can only be added from applications received by this company; assigning talent creates a new company campaign application without claiming the candidate applied independently.

Website submissions for jobs published by the campaign screens are imported explicitly using “Đồng bộ hồ sơ ứng tuyển”. Import is idempotent, up to 500 submissions at a time. These jobs share campaign IDs; historical jobs with independent IDs cannot be mapped automatically to historical campaigns. Existing original JobApplications are displayed directly. Campaign statistics exclude already-imported duplicate submissions. Stage moves and scheduling set the corresponding website submission to `interview` and record review time so candidate my-jobs reflects the transition. Stages are recorded in application history.

Calendar times use Vietnam UTC+7. Schedule requires a future start, end after start, duration at most 12 hours and a room or HTTP(S) meeting URL. Overlapping interviews for the same candidate or exact room name return 409; relational checks and inserts use a serializable transaction. New interview status is `pending`, consistent with candidate confirmation. Cancellation persists `cancelled`. Feedback is stored per interviewer and requires the interview to have started; score is 0–10. A cancelled interview cannot be evaluated.

CV viewer uses the submitted snapshot when available; online JSON is rendered as escaped React text and uploaded PDF is previewed/downloaded as PDF. Notes/readiness are persisted in the company's talent pool. Mail icons open an email draft; no emails are sent automatically. No Google/Exchange synchronization, reminder delivery, automatic AI screening or fabricated AI score is claimed. A stored MatchScore can be displayed/sorted when present.

No migration is required: existing TalentPoolEntry, JobApplication, ApplicationStageHistory, Interview and InterviewFeedback tables are used. Restart the normal user-run backend to load new endpoints. No additional long-lived backend is started for validation.

Verification: `npm run check`; Playwright `employer-candidates.spec.js` covers initial requests once under StrictMode, selecting/moving candidates, submitted CV, schedule timezone, failed note save preserving input, assignment, feedback and mobile overflow. `EmployerCandidatesTests` covers import idempotency, non-duplicated campaign statistics, stage history/submission status, schedule conflict, candidate confirmation, cancellation, evaluation and cross-company CV/application isolation. Backend verification uses CodexVerify and disposed test hosts.
